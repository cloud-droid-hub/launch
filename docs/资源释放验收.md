# openat计时资源释放验收

问题：原计时循环每项打开5000次`/dev/null`，没有释放成功返回的描述符。固定1.1.9／119连续检测达到32768上限后，打开详情发生SIGABRT6；原包保持。

修正：两项接口分别保存成功或失败的返回值，结束计时后关闭非负描述符；无效次数返回0。内部名称为`benchOpenRaw`及`benchOpenLib`，JNI导出名称保持；Java调用、5000次输入、3.0阈值、评分及页面逻辑保持。

输入：2026-10-03，登记源码1.2.1／121，`main`；AndroidNDKr29、revision29.0.14206865、Clang／LLD21.0.0。行为程序包含实际计时头文件，由Go测试编译、传输并核对输出。M4Pro、macOS15.7.9、arm64、HVF，GuestAndroid15、普通UID2000、Enforcing，自有标准ADB127.0.0.1:5783。

步骤：修正前编译原接口程序；先执行该制品，再重新编译修正实现。每项五轮，每轮5000次；另以768描述符上限执行失败返回路径，分别传入0及－1。

| 用例 | 原实现 | 修正实现 |
| --- | --- | --- |
| direct syscall，32768上限 | 5→5005→10005→15005→20005→25005，退出1 | 五轮均5，退出0 |
| libc，32768上限 | 同样增至25005，退出1 | 五轮均5，退出0 |
| direct syscall／libc，768上限 | 资源耗尽后无法读取描述符目录，两项退出2 | 两项五轮均5，退出0 |
| 次数0，两种接口 | 两项均0、描述符5 | 两项均0、描述符5 |
| 次数－1，两种接口 | 两项出现负计时，行为测试失败 | 两项均0、描述符5 |

原行为测试整体退出1、0.908秒；修正后三组八个子项整体退出0、2.037秒。完整JNI源文件的Androidarm64语法编译退出0。

原始记录位于[资源泄漏缺陷](https://github.com/cloud-droid-hub/launch/issues/1)。源码APK构建、新样本身份、独立安装双轮、每轮至少五次检测及详情打开、正常停止仍未完成；本项结果不代替整App验收。
